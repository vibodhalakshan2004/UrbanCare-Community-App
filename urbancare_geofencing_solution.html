The Problem
Why Naive Approaches Fail
Two obvious approaches both have serious engineering problems. Neither is acceptable for a production app.
❌ Approach A — Continuous GPS Polling
🔋Polls GPS every 10–30 seconds. GPS hardware stays active constantly — drains 15–25% battery per hour alone.
📡Each poll = HTTP request to FastAPI = network call = radio wake = more battery drain.
💸Millions of DB queries. PostGIS geo-query running every 30 seconds per user = server overload at scale.
🚫Android/iOS aggressively kill background apps doing continuous GPS. Notifications never arrive.
❌ Approach B — Server Push (FCM to All)
📍Server has no reliable idea where users currently are. Would need to push to everyone within a region.
🔔Massive notification spam — user gets alerts for issues 5km away. Uninstall rate goes up.
🗄️Requires storing current user location in server DB, updated constantly — privacy concern + storage cost.
⚡FCM quota limits. Can't push to 10,000 users every time someone reports a pothole.
The Engineering Solution
OS Geofencing + On-Device Cache
Your instinct was right — cache complaint locations on the device. The key insight is to use OS-level geofencing instead of manual GPS polling. The OS monitors virtual circles around saved locations using cell towers and Wi-Fi (not GPS) — this is how Google Maps, Uber, and Snapchat do location-aware notifications.

PostGIS Role
How PostGIS Fits In
🐘 PostGIS runs exactly ONCE — on app open
PostGIS is perfect for the initial sync query. When the app opens, it fires one efficient geo-query to get all active issue locations within 5km. The ST_DWithin function uses the GiST spatial index — making this query extremely fast even with thousands of complaints. The result is a tiny JSON payload (just IDs + coordinates) that fits in device memory easily.
SQL PostgreSQL / PostGIS — geofence sync query 
-- New VIEW: active_complaint_points (lightweight, only what device needs)
CREATE VIEW active_complaint_points AS
SELECT
  c.complaint_id,
  c.issue_type,
  c.status,
  l.latitude,
  l.longitude,
  l.geom,
  l.address
FROM complaints c
JOIN locations l ON l.location_id = c.location_id
WHERE c.status NOT IN ('fixed', 'closed', 'rejected');

-- The FastAPI endpoint runs this query (uses GiST index on geom — very fast)
SELECT
  complaint_id,
  issue_type,
  status,
  latitude,
  longitude,
  address
FROM active_complaint_points
WHERE ST_DWithin(
  geom,
  ST_MakePoint(:lng, :lat)::geography,
  5000   -- 5km radius (can be configured per user)
)
ORDER BY ST_Distance(geom, ST_MakePoint(:lng, :lat)::geography)
LIMIT 50;   -- max 50 geofences per user (OS limit is 100 on iOS)
Python FastAPI — geofence sync endpoint 
@router.get("/complaints/geofence-sync")
async def geofence_sync(
  lat: float,
  lng: float,
  db: AsyncSession = Depends(get_db),
  current_user = Depends(get_current_user)
):
  """
  Called ONCE when app opens. Returns lightweight list of
  active complaint lat/lngs within 5km for on-device geofencing.
  Typical response size: ~3KB for 50 complaints.
  """
  result = await db.execute(text("""
    SELECT complaint_id, issue_type, status, latitude, longitude, address
    FROM active_complaint_points
    WHERE ST_DWithin(geom, ST_MakePoint(:lng, :lat)::geography, 5000)
    ORDER BY ST_Distance(geom, ST_MakePoint(:lng, :lat)::geography)
    LIMIT 50
  """), {"lat": lat, "lng": lng})

  return {
    "complaints": [dict(row) for row in result.mappings()],
    "synced_at": datetime.utcnow().isoformat(),
    "expires_in_minutes": 30   # tell Flutter when to refresh
  }

@router.get("/complaints/{complaint_id}/status")
async def get_complaint_status(complaint_id: str, db = Depends(get_db)):
  """Tiny check called when user enters geofence. ~50 bytes response."""
  result = await db.execute(
    text("SELECT status FROM complaints WHERE complaint_id = :id"),
    {"id": complaint_id}
  )
  row = result.fetchone()
  return {"status": row.status if row else "not_found"}

Dart core/services/geofence_service.dart 
// pubspec.yaml additions:
// geofence_service: ^4.0.0     ← handles OS geofencing
// sqflite: ^2.3.0              ← on-device SQLite cache
// geolocator: ^11.0.0          ← one-shot GPS on app open only

class ProximityNotificationService {
  static final GeofenceService _geofenceService = GeofenceService.instance.setup(
    interval: 5000,           // check every 5s ONLY when near boundary
    accuracy: 100,            // 100m accuracy (uses WiFi/cell, not GPS)
    loiteringDelayMs: 60000,  // wait 1min before trigger (avoid false positives)
    statusChangeDelay: 10000, // debounce — prevents repeat notifications
    useActivityRecognition: true,  // skip when user is stationary
    allowMockLocations: false,
    printDevLog: false,
  );

  /// Call this ONCE when app opens/resumes. Not on every screen change.
  static Future<void> syncAndRegisterGeofences() async {
    // 1. Check if cache is still fresh (< 30 minutes old)
    if (await _isCacheFresh()) {
      await _registerFromCache();  // re-register from SQLite, no API call
      return;
    }

    // 2. Get current position — ONE shot, not continuous stream
    final position = await Geolocator.getCurrentPosition(
      desiredAccuracy: LocationAccuracy.medium,  // medium = faster + less battery
      timeLimit: const Duration(seconds: 10),
    );

    // 3. One API call to FastAPI/PostGIS
    final response = await ApiClient.dio.get(
      '/api/v1/complaints/geofence-sync',
      queryParameters: {'lat': position.latitude, 'lng': position.longitude},
    );

    final complaints = (response.data['complaints'] as List)
        .map((e) => GeofencePoint.fromJson(e))
        .toList();

    // 4. Save to device SQLite
    await GeofenceCache.save(complaints);

    // 5. Register geofences with OS
    await _registerGeofences(complaints);
  }

  static Future<void> _registerGeofences(List<GeofencePoint> points) async {
    final geofences = points.map((p) => Geofence(
      id: p.complaintId,
      latitude: p.latitude,
      longitude: p.longitude,
      radius: [
        GeofenceRadius(id: 'r100', length: 100),  // notify at 100m
      ],
    )).toList();

    // Register callback — fires when user enters any geofence
    await _geofenceService.start(geofences).then((_) {
      _geofenceService.addGeofenceStatusChangedListener(_onGeofenceEntered);
    });
  }

  /// Fires when user physically enters a 100m circle
  static Future<void> _onGeofenceEntered(
    Geofence geofence,
    GeofenceRadius radius,
    GeofenceStatus status,
    Location location,
  ) async {
    if (status != GeofenceStatus.ENTER) return;

    // Verify complaint is still active (tiny API call, ~50 bytes)
    final res = await ApiClient.dio.get('/api/v1/complaints/${geofence.id}/status');
    final complaintStatus = res.data['status'];

    if (['fixed', 'closed', 'rejected'].contains(complaintStatus)) {
      // Issue resolved — remove this geofence silently
      _geofenceService.removeGeofenceById(geofence.id);
      return;
    }

    // Get issue details from local cache (no API call)
    final cached = await GeofenceCache.getById(geofence.id);

    // Show local notification (no FCM needed for this)
    await LocalNotificationService.show(
      id: geofence.id.hashCode,
      title: '${cached?.issueTypeEmoji} Unresolved issue nearby',
      body: '${cached?.issueType} reported ~100m away. Tap to view or confirm.',
      payload: 'complaint:${geofence.id}',
    );
  }
}
Dart core/services/geofence_cache.dart — on-device SQLite store 
class GeofenceCache {
  static Database? _db;

  static Future<Database> get db async {
    _db ??= await openDatabase(
      'geofence_cache.db',
      version: 1,
      onCreate: (db, _) => db.execute('''
        CREATE TABLE geofence_points (
          complaint_id  TEXT PRIMARY KEY,
          issue_type    TEXT NOT NULL,
          latitude      REAL NOT NULL,
          longitude     REAL NOT NULL,
          address       TEXT,
          cached_at     INTEGER NOT NULL   -- epoch ms for freshness check
        )
      '''),
    );
    return _db!;
  }

  /// Cache is fresh if saved less than 30 minutes ago
  static Future<bool> isFresh() async {
    final d = await db;
    final rows = await d.query('geofence_points', orderBy: 'cached_at DESC', limit: 1);
    if (rows.isEmpty) return false;
    final age = DateTime.now().millisecondsSinceEpoch - (rows.first['cached_at'] as int);
    return age < 30 * 60 * 1000;  // 30 minutes
  }

  static Future<void> save(List<GeofencePoint> points) async {
    final d = await db;
    final now = DateTime.now().millisecondsSinceEpoch;
    await d.delete('geofence_points');  // clear old cache
    for (final p in points) {
      await d.insert('geofence_points', {
        'complaint_id': p.complaintId,
        'issue_type':   p.issueType,
        'latitude':     p.latitude,
        'longitude':    p.longitude,
        'address':      p.address,
        'cached_at':    now,
      }, conflictAlgorithm: ConflictAlgorithm.replace);
    }
  }
}

Edge Cases & Refinements
Real Engineering Considerations
⏰ Cache Staleness
If an issue gets fixed while user has stale cache, the geofence still exists on device. The status check API call (step 7 in flow) catches this — it silently removes the geofence without showing notification. User never sees a false alert.
📱 iOS Limit: 20 Geofences
iOS limits apps to 20 simultaneous geofences. Solution: sort PostGIS results by ST_Distance() and only register the 20 nearest issues. As user moves and some drop out of range, refresh the list. Android limit is 100.
🔇 Notification Fatigue
User should not get the same notification twice for the same issue. Track in SQLite: last_notified_at per complaint. Only trigger again if 24 hours have passed or user explicitly dismissed and re-approached.
📴 No Internet on Trigger
Geofence triggers even offline. In _onGeofenceEntered, if the status check API call fails (no internet), fall back to cached status. If cached status is still active, show notification. It's better to show a slightly stale notification than none.
🔄 New Issues Added
New complaints reported after the last sync won't be in the device cache yet. FCM push notification handles this: when a new complaint is reported, FastAPI sends a FCM notification to nearby citizens with the complaint_id — Flutter receives it, adds it to local cache and registers a new geofence.
🛑 User Opted Out
Always check notification permission before registering geofences. If user denied location permission, skip geofencing entirely. Add a settings toggle "Nearby Issue Alerts" in the profile screen — stores preference in flutter_secure_storage.
💡
Summary — The full chain: App opens → one GPS shot → one PostGIS query → save 50 points to SQLite → register OS geofences → phone sleeps → OS wakes app when you walk past a pothole → one status check → local notification. No continuous GPS. No continuous server polling. Battery impact ≈ 3% per hour from location. This is exactly how Google Maps, Snapchat, and Uber handle proximity-aware features.
